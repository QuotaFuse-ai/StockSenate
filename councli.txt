一、项目基础信息
1.1 项目定位
QuotaFuse Council 是 simonlin1212/TradingAgents-astock 的原地重写增强版 [R1]：
内置 7 角色、多空辩论、研究经理、交易员、三档风险辩论、投资经理终审完整保留；

数据采集统一交给 QuotaFuse StockData，不在本组件重复实现采集、缓存、代理池、降级 [R2]；
支持 StockData 与本地 JSON/文档/TXT/数据库可插拔、可混合、可实时采集；

设计理由：
避免重复建设：采集、缓存、代理池是 StockData 的核心能力，Council 再建一套只会增加维护成本和故障点。
单一数据真相源：风险事件、字段映射由 StockData 统一生产和定义，Council 只消费结构化结果，保证多角色拿到的数据一致。
职责分离：健康检查、熔断、切源由 StockData 执行；Council 读取 data_source_status、source、freshness 并据此标注报告缺口和置信度，不重复维护状态机。
可替换性：只要 StockData 输出契约稳定，Council 不关心底层是东财、巨潮还是通达信；更换数据源不影响上层分析逻辑。
原则：Council 不直连东财/巨潮/通达信，所有行情、财报、公告、研报、资金、风险事件统一经 DataAccessLayer 向 StockData 或本地 Provider 获取 [R2]。

2.2 必须修正的细节
propagate 返回结构
既有 propagate 返回 (final_state, decision) 元组。改造后必须保持该返回值签名不变；summary.json、complete_report.md 是衍生输出，不是替代返回值。验收时需做返回值契约测试。
角色模型配置粒度
既有实现已支持 role_llms 细粒度配置，可为单个角色指定不同供应商模型。Council 必须继承并兼容该能力，不能只保留“快思考/深思考”两级。
performance 不是回测
现有 README 明确说明该功能是决策事后归因统计，不是回测、不是策略业绩。Council 文档中“完整回测引擎”是新增能力，必须与 performance 分开描述、分开验收，不能混为一谈。
数据获取是内建模式，迁移是架构重构
既有实现自带 A 股数据供应商并直连免费源。Council 将其迁移到 StockData 底座属于架构重构，不是简单新增功能；需评估对原数据质量测试的影响，并保留迁移期兼容开关。
项目定位是研究框架，不是产品
既有实现强调面向研究与教学、不构成投资建议、不产出可执行价位。Council 对外表述必须延续该边界，避免用户产生“荐股”预期。

七、数据源可插拔与 StockData 对接
7.1 设计结论
不是“二选一硬编码”，而是 可插拔 DataProvider + 统一数据契约 + 可配置路由 + 全量溯源。支持纯 StockData、纯本地数据、优先级 fallback、混合模式、实时 StockData 采集。
7.2 DataProvider 组成
text
TradingAgent 上层
   → DataAccessLayer（统一 DataEnvelope + 路由 + 溯源）
       ├── StockDataProvider：MCP stdio/http 或 local import
       ├── JsonFileProvider：本地 JSON 归档
       ├── TextDocProvider：TXT/MD/PDF/Word，仅文本分析
       ├── SqlProvider：SQLite/MySQL/Postgres，只读优先
       └── CompositeProvider：按优先级/字段级路由
7.3 统一数据契约 DataEnvelope
python
class DataEnvelope(BaseModel):
    domain: str          # kline / financial / announcement / risk_event ...
    code: str
    data_as_of: date
    payload: dict
    source: str          # stockdata / json / text_doc / sql
    source_detail: str
    fetched_at: datetime
    freshness: str       # realtime / cached / archive
    confidence: str      # high / medium / low
    data_source_status: str  # ok / degraded / missing
上层角色只消费 payload，同时可读取溯源信息。报告标注数据来源和新鲜度。
7.4 路由配置 data_source.toml
toml
[data_source]
mode = "hybrid"        # stockdata | local | hybrid | priority
realtime_enable = true
realtime_timeout_sec = 30
realtime_fallback_to_local = true
local_root = "./data/local"
[data_source.sql]
enable = false
url = "sqlite:///./data/trading.db"
readonly = true
[data_source.priority]
kline = ["stockdata", "sql"]
financial = ["stockdata", "sql"]
announcement = ["stockdata", "local_json", "text_doc"]
research = ["stockdata", "text_doc"]
risk_event = ["stockdata", "sql"]
模式语义：
stockdata：只用 StockData；
local：只用本地数据，支持离线回放；
priority：按列表逐级 fallback；
hybrid：历史/归档优先本地，实时/缺失/刷新走 StockData。
7.5 实时使用 StockData 采集
运行形态<w:t>调用方式
独立进程/单机<w:t>stdio MCP 子进程 [R3][R4]
多 Agent/局域网<w:t>http MCP，带鉴权 [R3]
同进程嵌入<w:t>local import，注意阻塞风险
CLI/定时任务<w:t>qf-stockdata CLI 或 MCP tool call
关键规则：
realtime_enable=true 才允许分析中触发实时抓取；
先查缓存，未命中再采集；
分析开始前批量预取 K 线、财报、公告、风险事件；
实时超时自动 fallback 本地/缓存，标记 degraded；
多 Agent 并发依赖 StockData 防重复采集锁；
返回 freshness=realtime|cached|archive；
单类数据失败不阻塞整个流程，报告注明缺口。
7.6 本地数据接入
JSON：data/local/{domain}/{code}/{date}.json，schema 校验，适合离线回放和测试；
TXT/MD/PDF/Word：仅用于公告、研报、政策、新闻文本分析，可选用 Crawl4AI 清洗 [R18]；禁止从文本抽取财务数值、K 线、资金数值；
数据库：SQLite/MySQL/Postgres，只读优先，表映射和查询模板化 [R23]，适合回测库、决策记录库、历史归档库。
7.7 边界约束
数值类数据只允许来自 StockData 或结构化数据库；
文本类数据只用于分析和清洗，不参与数值抽取；
实时采集默认关闭，开启后必须有超时、降级、防重复锁；
所有数据必须带溯源元信息；
本地源不可用不得静默返回空，必须标记 data_source_status。
7.8 验收标准
mode=stockdata 不依赖本地数据可完成分析；
mode=local 断网可完成分析；
mode=hybrid 本地历史 + StockData 实时增量可混合；
实时超时能 fallback 并标注 degraded；
并发分析不重复采集；
文本数据不会被用于财务数值；
每条数据可追溯来源和抓取时间；
回测使用本地归档时结果可复现。

新增角色必须定义六件事：名称与提示词、工具白名单、Pydantic 输出 Schema [R7]、模型层级、阶段、是否参与辩论及权重。
8.3 工作流接入 workflow.toml
toml
[[workflow.nodes]]
id = "custom_macro"
role = "custom_macro"
type = "analyst"
parallel_group = "analyst_round_1"
[[workflow.edges]]
from = "custom_macro"
to = "debate_bull"
规则：
analyst 阶段角色默认并行执行；
新增角色不改变默认 7 角色拓扑；
新增角色若参与辩论，必须显式声明边；
辅助分析可只输出到报告附录；
节点 id 必须与 roles key 对应。
8.4 数量与预算约束
默认角色上限 12 个（7 内置 + 5 自定义），可配置；
新增角色计入任务熔断的 LLM 调用次数和 Token 预算；
超限时配置校验报错；
自定义角色失败可跳过，不阻塞主流程，报告标注 partial。
8.5 工具权限隔离
每个角色只能调用白名单内工具；
StockData 工具按角色授权；
越权调用返回结构化错误并审计；
自定义角色默认只读；
白名单变更需审计。
8.6 验收标准
默认 7 角色行为不变；
新增自定义角色后 qfc analyze 可运行；
角色可启停、调权重；
越权调用被拒绝并审计；
Schema 校验失败只重试当前节点；
新增角色后默认 7 角色回归通过；
超上限配置报错；
自定义角色失败不阻塞主流程。
九、工作流与配置
workflow.toml 定义并行、串行、分支、汇聚、辩论轮次、收敛阈值、终止条件、interrupt 节点；
辩论智能收敛：每轮输出分数，达到阈值提前结束，记录终止原因；
事实交叉核验钩子：数值结论必须来自结构化数据，文本结论标注来源，冲突标记 conflict；
人工介入工单：LangGraph interrupt 可配置，工单存储、通知、恢复、超时、权限、审计 [R5]；
配置统一 toml，提供 JSON Schema 校验和迁移脚本。
十、MCP Server 设计
双传输：stdio / Streamable HTTP [R3][R4]；
stdio 模式 stdout 只输出 MCP 协议报文，日志走 stderr；
暴露工具：分析任务、回测、告警查询、报告查询、配置查询；
与 StockData MCP 分开命名、分开鉴权、分开日志，通过 trace_id 串联；
http 模式默认 127.0.0.1，对外必须鉴权；
验收：至少一个 MCP 客户端能列出并调用工具。
十一、CLI 与 Python API
bash
qfc analyze 600000 --date 2024-12-31
qfc analyze 600000 --date 2024-12-31 --disable custom_macro
qfc analyze 600000 --date 2024-12-31 --enable custom_macro --weight 0.6
qfc role list
qfc role show basic
qfc role validate
qfc role enable custom_macro
qfc role disable custom_macro
qfc backtest run --code 600000 --start 2024-01-01 --end 2024-12-31
qfc alert list
qfc alert rules validate
qfc report diff --code 600000 --from 2024-11-30 --to 2024-12-31
qfc queue status
qfc queue submit --file tasks.csv
qfc mcp stdio
qfc mcp http --port 8765
qfc config validate
qfc config migrate
Python API：
CouncilGraph.propagate(code, date) 为主类；
保留 TradingAgentsGraph 别名，propagate 签名和返回 (final_state, decision) 不变；
CLI 输出 json/table/csv，结果走 stdout，日志走 stderr；
退出码：0 成功、2 参数错误、3 配置错误、4 数据源不可用、7 限流、8 部分失败。
十二、完整回测引擎
数据模型：decision_record、backtest_run、backtest_trade、backtest_position、backtest_metric、price_series、benchmark_series。
功能：滑点、手续费、仓位、重叠窗口控制；收益曲线、方向准确率、alpha 分组、Buy→Sell alpha 衰减；基于已保存决策自动回测；data_as_of 历史时点推演；回测数据优先本地归档，缺失走 StockData；Streamlit 回测页面 [R6]。
验收：固定数据集可复现、无未来函数、参数生效、无样本泄漏、报告与 WebUI 一致。注意：performance 是事后归因，不是回测，二者分开验收。
十三、告警规则引擎
toml
[[alert.rule]]
id = "unlock_near"
level = "high"
condition = "risk_event.type == 'unlock' and days_to_unlock <= 30"
action = ["json", "webui", "webhook"]
dedup_hours = 24
能力：high/mid/low；条件覆盖解禁、减持、预亏、商誉、处罚、政策利空、评级下调；动作 JSON + WebUI + Webhook；去重；状态机触发/确认/恢复/静默；Webhook 重试、签名、幂等；依赖 StockData 风险事件字段。
验收：规则可配置、去重生效、Webhook 可重试、告警与报告一致。
十四、报告、增量分析与多格式输出
报告版本快照：每次分析保存结构化快照；
Diff 对比：字段级差异、结论变化、风险变化；
增量分析：新标的完整流程；重复标的只拉新增数据并注入历史结论摘要；
多格式输出：精简结论、完整辩论、风险清单、Diff 摘要；
验收：二次分析 token 显著下降，Diff 可读，输出格式可切换。
十五、任务熔断与批量队列
任务分级熔断：最大调用次数、最大 Token、超时优雅退出；
批量队列：并发控制、限速、失败重试/跳过、进度查询；
与 StockData 限流、缓存、防重复锁协同；
验收：批量任务可暂停/恢复/取消，失败可追踪。

17.3 部署
Docker Compose 启动 qf-council、webui、redis，可选 stockdata、日志库 [R25]；监控分析耗时、LLM 调用、Token、节点失败率、数据源降级率、回测任务数、告警数；日志支持 file/sqlite/mysql/postgres；配置变更审计和回滚。
17.4 边界约束
只做投研分析 + 回测推演，不做实盘交易下单，不输出自动交易指令；
财务、K 线、资金数值只来自 StockData 或结构化数据库，绝不从 TXT/文档 AI 抽取；
文本类数据仅用于公告、研报、政策、新闻分析；
增强模块带开关，关闭零开销；
实时采集默认关闭，开启后必须有超时、降级、防重复锁；
所有数据带溯源元信息；
MCP stdio stdout 只输出协议报文；
“能力完整/Issue 闭环”以接口契约和回归测试验收；
原仓库许可证与兼容实现边界需确认；
不重复实现 StockData 的采集、缓存、代理池、降级能力。
