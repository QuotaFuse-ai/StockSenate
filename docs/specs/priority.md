# 需求优先级

分级标准：

- **P0** — 缺此项则产品不成立，或安全/合规边界被破坏；未完成不进入验收。
- **P1** — v1.0 正式版必须完整交付的企业级能力；可分批但不可砍。
- **P2** — 增强项，允许排到 v1.1；砍掉不影响核心闭环。

排序原则（按权重大小）：**安全与边界 > 可运行闭环 > 数据可信 > 成本可控 > 体验与扩展**。

## 4. 明确不做（MoSCoW: Won't）

| 项 | 原因 |
|---|---|
| 实盘下单、券商对接、资金划转 | 产品定位与合规边界 |
| 建仓价/止损位/目标价/仓位建议 | 代码级不产出，避免被当投资建议 |
| 自建行情采集、代理池、缓存层 | 与 TickHub 重复，且不在本项目职责 |
| 托管 SaaS、代跑分析 | 不接触用户运行结果 |
| `[google]` extra | httpx 结构性冲突，无法同时满足（DEC-007） |
| 预生成个股报告随仓库发布 | 只发布可自行运行的脚本 |

## 5. 交付顺序与依赖

```
M0 契约层（P0 #1-#6, #10, #14, #15）
      │
      ├── M1 数据 + 分析闭环（P0 #7-#13, #16, #18；P1 #24, #26）
      │        │
      │        ├── M2 质量与运维（P0 #17, #19, #21, #22；P1 #25, #27, #29-#32）
      │        │
      │        └── M3 回测/队列/WebUI（P0 #20；P1 #28, #33-#35）
      │
      └── M4 发布与全量验收（P0 #23；P2 #36）
```

**关键路径**：`DataEnvelope` → Provider 接入 → 图节点 → 报告 → 回测。回测依赖报告里的 `decision_record` 与 `data_as_of`，因此不能先于报告完成。

**可并行**：CLI 骨架、配置校验、日志脱敏、CI 与打包在 M0 即可与其他线并行；WebUI 可在报告结构冻结后并行。

## 6. 排期建议（按 2 人后端 + 1 前端 + 1 测试）

| 周期 | 目标 | 交付判定 |
|---|---|---|
| 第 1 周 | M0 契约层 | `ssenate --help`、`config validate`、契约单测、CI 绿 |
| 第 2–3 周 | M1 单标的闭环 | 一只标的端到端出五分区报告，含数据附录与 `partial` 标记 |
| 第 4 周 | M2 质量与告警 | 质量闸门、HITL、告警试跑、MCP 五工具 |
| 第 5–6 周 | M3 回测/队列/WebUI | 回测可复现；队列 50 任务跑通；WebUI 九页 |
| 第 7 周 | M4 发布验收 | 打包、compose、逐项勾选验收矩阵、安全复核 |

> 排期是建议值，实际以里程碑退出标准为准；不按日期压缩验收项。
