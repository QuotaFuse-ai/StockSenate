# DEC-006 不输出可执行价位，不产出交易指令

- 状态：已采纳
- 日期：2026-10-26
- 影响版本：0.1.0+

## 背景

StockSenate 定位为「只做投研分析 + 回测推演，不做实盘交易下单」。但 LLM 生成的分析天然倾向于给出「建仓价 X、止损 Y、目标 Z、仓位 N%」这类看似专业的表述，一旦进入报告就会越过产品边界，也会带来合规风险。

## 决策

1. **禁止字段**：`建仓价`、`止损位`、`目标价`、`仓位比例`，以及任何等价表述（入场区间、止盈点、加仓比例等）不得出现在报告、WebUI、MCP 返回与告警中。
2. **不提供下单能力**：仓库内不引入券商 SDK、不定义下单接口、不保存账户与资金信息。
3. **结构化约束**：`config/output_template.toml` 的 `sections.trade.forbidden_fields` 至少包含 `order_id`、`broker_account`、`auto_order`；`config validate` 缺失即失败。
4. **出口过滤**：报告渲染前与合规过滤层各做一次检查，命中即替换为定性描述并记审计事件。
5. **允许的方向性结论**：`Buy` / `Hold` / `Sell` 评级、看多/看空理由、风险清单、需要跟踪的指标与事件——这些是研究结论，不是交易指令。
6. **免责声明强制**：每份报告与 WebUI 页面固定展示「研究框架，非投资建议；不构成任何交易指令」。

## 反例与改写

| 禁止 | 改写为 |
|---|---|
| 「建议 12.5 元建仓，止损 11.8」 | 「估值处于近三年 30% 分位，需关注下季度毛利率能否企稳」 |
| 「仓位控制在三成」 | 「该标的不确定性较高，适合作为观察对象而非核心持仓」 |
| 「目标价 18 元」 | 「若行业景气度回升，盈利弹性主要来自 XX 业务」 |

## 后果

- 安全工程师按附录 A 的 S-01、S-02 复核，可自动化扫描字段与关键词。
- 回测引擎仍可计算收益与净值（那是历史推演），但输出的交易记录属于回测内部数据，不得包装成「建议操作」。
- 提示词需在系统层显式约束，不能只靠后置过滤。
