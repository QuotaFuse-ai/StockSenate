# DEC-004 回测与 performance 是两件事

- 状态：已采纳
- 日期：2026-10-26
- 影响版本：0.1.0+

## 背景

常见实现把「事后归因」与「历史推演」混在同一个 `performance` 概念里，验收时无法区分「策略在过去有效」与「这次分析的结论事后看对不对」。文档 v1.2 第十二章要求完整回测引擎，第二章又明确 `performance` 只是事后归因。

## 决策

| 维度 | `backtest` | `performance` |
|---|---|---|
| 输入 | 历史已保存决策 + 行情序列 | 单次或多次已完成分析的决策 |
| 时间 | 按 `data_as_of` 逐时点重放 | 分析日之后的一段真实行情 |
| 输出 | 净值曲线、交易明细、方向准确率、alpha 分桶、Buy→Sell alpha 衰减 | 方向命中、幅度偏差、分角色贡献 |
| 未来函数 | 必须严格禁止，注入未来数据即失败 | 允许使用分析日之后的数据（本就事后） |
| 对外 | `ssenate backtest run` | `ssenate performance` |
| 依赖 | `[backtest]` extra | 无额外依赖 |

两条命令、两份报告模板、两套验收清单，不共用「收益」措辞。回测报告不得出现「推荐」「预期收益」；归因报告不得出现「净值」。

## 后果

- 用户不会把事后归因误读为策略验证。
- 回测引擎必须实现滑点、手续费、最小手数、T+1、涨跌停等 A 股约束，归因不需要。
- 测试工程师的两份验收清单互相独立，任一方失败不牵连另一方。
